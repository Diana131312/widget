# Оплата с расчётного счёта

Базовый адрес: `https://app.gettime.online/api/widget`. Авторизация не нужна, организация определяется по alias `les`. JSON, camelCase, даты `yyyy-MM-dd`, суммы в рублях.

Кнопку показываем только если `GET /get/{alias}` вернул `invoicePayment: true`. Иначе запросы отвечают 400 «Оплата по счёту недоступна».

## Сценарий в виджете

1. На шаге оплаты гость выбирает «Оплата с р/счета юр. лица» и указывает почту для счёта.
2. Бронь создаётся обычным `POST /save` или `POST /daily-save` с `paymentMode: "full"`.
3. Пока счёт не выставлен, на шаге ожидания идёт обратный отсчёт `timeoutMinutes`. Счёт нужно выставить до конца таймера.
4. `POST /invoice/offer` показывает, можно ли выставить всю сумму.
5. Подсказки организации: `GET /invoice/suggest/{alias}?query=`.
6. `POST /invoice/create` возвращает ссылку на PDF. То же письмо уходит на почту покупателя.
7. После выставления счёта бронь больше не отменяется по таймеру. Деньги отмечает администратор вручную.

## POST /invoice/offer

```json
{
  "alias": "les",
  "bookingIds": ["guid"],
  "dailyBookingIds": ["guid"],
  "phone": "+79991234567"
}
```

Достаточно одного из массивов: `bookingIds` — почасовая баня, `dailyBookingIds` — дом. `phone` должен совпасть с телефоном заказа по последним 10 цифрам.

Сертификат оплачивается только ссылкой из `POST /save-certificates`. Выбор оплаты с р/счёта на сертификате не показываем: API для счёта по сертификату ещё не готово.

Ответ: `orderNumber`, `prepayAmount` (null, если предоплаты нет), `fullAmount` (null, если полную сумму выставлять нельзя), `paymentDays`.

## POST /invoice/create

`mode`: `"full"`, если в offer пришёл `fullAmount`, иначе `"prepay"` (если предоплаты нет, сервер берёт всю сумму).

`buyer`: `name` (до 300), `inn` (10 или 12 цифр), `kpp` (9 цифр, обязателен при ИНН из 10 цифр, для ИП не нужен), `address` (до 500), `email`.

Ответ: `documentId`, `number`, `date`, `dueDate`, `amount`, `buyerName`, `pdfUrl`. Ссылку открываем как `https://app.gettime.online` + `pdfUrl`. Параметр `t` обязателен.

Повтор с тем же ИНН и суммой возвращает уже выставленный счёт. На заказ не больше 5 счетов. Лимит — 100 выставлений в час.

## GET /invoice/suggest/{alias}?query=

```json
[{ "name": "ООО «Ромашка»", "inn": "7707083893", "kpp": "773601001", "address": "г. Москва, ул. Ленина, д. 1", "type": "LEGAL" }]
```

`type`: `LEGAL` — организация, `INDIVIDUAL` — ИП. Пустой массив — гость заполняет реквизиты сам.

## Ошибки

400 с обычным текстом, не JSON. Текст показываем гостю. Примеры: «Оплата по счёту недоступна», «Бронирование не найдено», «Бронь уже отменена: время на оплату истекло. Оформите бронирование заново», «Проверьте ИНН», «Укажите КПП (9 цифр)», «Укажите юридический адрес», «Проверьте e-mail», «Нет суммы к оплате», «Заказ уже оплачен», «По заказу уже выставлено несколько счетов. Свяжитесь с администратором», «Слишком много запросов. Попробуйте позже».
